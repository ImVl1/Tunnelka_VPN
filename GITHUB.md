# Как выложить Tunnelka на GitHub через браузер и получить установщик

Ничего устанавливать не нужно: GitHub сам соберёт установщик для Windows на своих серверах. Понадобятся браузер и архив `tunnelka.zip`. Всё занимает около 20 минут, из них 15 — ожидание сборки.

## 1. Подготовьте файлы

1. Распакуйте `tunnelka.zip` (правой кнопкой → «Извлечь всё»).
2. Откройте папку `tunnelka`. Внутри должны быть `core`, `src-tauri`, `ui`, `extension`, `scripts`, `README.md`, `Cargo.toml` и другие файлы.
3. Включите показ скрытых файлов, чтобы видеть папку `.github`: в Проводнике «Вид» → «Показать» → «Скрытые элементы». Она понадобится в шаге 4.

## 2. Создайте аккаунт

Зарегистрируйтесь на https://github.com (кнопка Sign up) и подтвердите почту. Если аккаунт уже есть — войдите.

## 3. Создайте репозиторий

1. Нажмите «+» в правом верхнем углу → **New repository**.
2. **Repository name**: `tunnelka`.
3. Видимость:
   - **Public** — сборка бесплатна без ограничений, код видят все.
   - **Private** — код видите только вы; бесплатно 2000 минут сборки в месяц, сборка под Windows тратит их вдвое быстрее (одной сборки ≈ 30 минут лимита хватит с запасом).
4. Галочки «Add a README», «.gitignore», «license» **не ставьте** — эти файлы уже есть в архиве.
5. Нажмите **Create repository**.

## 4. Загрузите файлы

1. На странице пустого репозитория нажмите ссылку **uploading an existing file** (в строке «…or create a new file or uploading an existing file»).
2. В Проводнике откройте папку `tunnelka`, выделите **всё её содержимое** (Ctrl+A) и перетащите в окно браузера. Перетаскивайте именно содержимое, а не саму папку `tunnelka` — иначе всё окажется на уровень глубже и сборка не запустится.
3. Дождитесь, пока под полем загрузки появится список всех файлов (около 50).
4. Внизу в поле **Commit changes** можно ничего не менять. Нажмите зелёную кнопку **Commit changes**.

### Проверьте, что загрузилась папка `.github`

Браузеры иногда пропускают скрытые папки. На главной странице репозитория должна быть папка `.github`. Если её нет:

1. Нажмите **Add file** → **Create new file**.
2. В поле имени файла напечатайте `.github/workflows/build.yml` — после каждого `/` GitHub сам превратит текст в папку.
3. Откройте на компьютере файл `tunnelka\.github\workflows\build.yml` в Блокноте, скопируйте всё (Ctrl+A, Ctrl+C) и вставьте в большое поле на GitHub.
4. Нажмите **Commit changes…** → ещё раз **Commit changes**.

## 5. Дождитесь сборки

1. Откройте вкладку **Actions** вверху репозитория.
2. Если GitHub спросит, включить ли workflows, нажмите **I understand my workflows, go ahead and enable them**.
3. В списке появится запуск **Build** с жёлтым кружком — идёт сборка. Если его нет, слева выберите **Build** → справа **Run workflow** → **Run workflow**.
4. Через 10–20 минут кружок станет зелёной галочкой.

Если появился красный крестик — откройте запуск, нажмите на шаг с ошибкой, скопируйте текст ошибки и пришлите его мне.

## 6. Скачайте установщик

1. Нажмите на запуск с зелёной галочкой.
2. Внизу страницы, в блоке **Artifacts**, нажмите **tunnelka-windows** — скачается zip-архив.
3. Внутри:
   - `Tunnelka_1.0.0_x64-setup.exe` — установщик приложения;
   - `tunnelka-extension.zip` — расширение для Chrome.

Артефакты хранятся 90 дней; скачать их можно, только войдя в аккаунт GitHub.

При установке Windows SmartScreen покажет «Система Windows защитила ваш компьютер» — установщик не подписан платным сертификатом. Нажмите **Подробнее** → **Выполнить в любом случае**.

## 7. (Необязательно) Постоянная ссылка на скачивание

Чтобы установщик лежал на странице релиза и его можно было скачивать без входа в аккаунт (для публичного репозитория):

1. На главной странице репозитория справа нажмите **Create a new release** (или **Releases** → **Draft a new release**).
2. **Choose a tag** → впишите `v1.0.0` → **Create new tag: v1.0.0 on publish**.
3. Заголовок — например, `Tunnelka 1.0.0`.
4. Нажмите **Publish release**.
5. Через 10–20 минут сборка сама прикрепит к релизу установщик и архив расширения.

Для следующей версии сделайте новый релиз с тегом `v1.0.1`, `v1.1.0` и т.д.

## 8. Как вносить изменения

- **Поправить один файл:** откройте его на GitHub → значок карандаша (Edit) → измените → **Commit changes**. Сборка запустится сама.
- **Заменить файлы новыми:** **Add file** → **Upload files** → перетащите файлы с тем же путём (например, содержимое новой версии папки `tunnelka`) → **Commit changes**. Одноимённые файлы заменятся.

Каждое изменение в ветке `main` запускает новую сборку — свежий установщик ищите в последнем запуске во вкладке **Actions**.

## Частые проблемы

| Что видите | Что делать |
|---|---|
| Во вкладке Actions пусто | Нет папки `.github/workflows` — создайте файл вручную (шаг 4) |
| Файлы оказались внутри папки `tunnelka/` в репозитории | Вы перетащили саму папку. Удалите репозиторий (Settings → внизу Delete this repository) и загрузите заново содержимое папки |
| Ошибка в шаге `npm run fetch-core` | Временный сбой загрузки с GitHub — нажмите **Re-run jobs** справа вверху |
| Ошибка в шаге `cargo test` или `npm run build` | Пришлите мне текст ошибки из лога |
| «Upload failed» при загрузке файлов | Загрузите папки частями: сначала `core`, `src-tauri`, затем остальное |
