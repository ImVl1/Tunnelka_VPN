# Tunnelka

VPN-клиент для Windows в духе Hiddify / v2RayTun / Happ: подписки, серверы VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, раздельное туннелирование по приложениям и сайтам. Плюс расширение для Chrome.

Ядра — [sing-box](https://github.com/SagerNet/sing-box) 1.14 и [Xray-core](https://github.com/XTLS/Xray-core) 26.10, интерфейс — Tauri 2 (Rust + HTML/JS).

## Возможности

**Подписки**
- ссылка на подписку из бота или личного кабинета (Marzban, Remnawave, 3x-ui, Hiddify и др.);
- форматы: список ссылок в base64 или текстом, JSON-конфиг sing-box, JSON-конфиги Xray (как у Happ/v2RayTun);
- заголовки `profile-title`, `subscription-userinfo` (трафик и срок), `profile-update-interval`, `support-url`, `profile-web-page-url`, `announce`;
- автообновление по интервалу, ручное обновление, загрузка через VPN, если панель недоступна напрямую;
- отдельные серверы можно добавить ссылками (группа «Мои серверы»).

**Протоколы:** VLESS (TCP, XHTTP, WS, gRPC, HTTPUpgrade, mKCP; REALITY, TLS, XTLS Vision, VLESS Encryption), VMess, Trojan, Shadowsocks (включая 2022, obfs, v2ray-plugin), Hysteria2 (obfs, port hopping), TUIC, SOCKS5, HTTP(S).

**Два ядра.** Основное — sing-box: TUN, раздельное туннелирование, DNS, большинство протоколов. Серверы, которые sing-box не умеет (XHTTP, VLESS Encryption, REALITY с ML-DSA), автоматически запускаются через Xray-core: для каждого такого сервера Xray открывает локальный SOCKS-вход, а sing-box подключается к нему. В настройках можно включить «Всегда Xray-core» — тогда через Xray пойдут все VLESS/VMess/Trojan-серверы (полезно, если какой-то REALITY-сервер нестабилен в sing-box). Сам Xray всегда ходит к серверам напрямую, мимо TUN, — петли не будет.

**Подключение**
- режим TUN — весь трафик компьютера через виртуальный адаптер;
- режим «Системный прокси» — без адаптера, через настройки прокси Windows;
- автовыбор лучшего сервера по задержке;
- переключение сервера на лету без разрыва (через Clash API ядра);
- проверка пинга: TCP-пинг без подключения, реальная проверка через сервер при подключении;
- скорость, время сессии, журнал ядра, значок в трее, автоподключение.

**Раздельное туннелирование (Windows)**
- по приложениям: «всё через VPN, кроме выбранных» или «только выбранные через VPN»;
- выбор из запущенных программ, по имени `.exe`, полному пути или целой папке;
- по сайтам: списки «через VPN» и «напрямую» (домены с поддоменами, IP, подсети, `keyword:`, `full:`, `regexp:`);
- российские сайты и IP напрямую (`.ru`, `.рф`, `.su` + базы geosite/geoip);
- локальная сеть всегда напрямую.

Правила применяются в таком порядке: локальная сеть → сайты «напрямую» → сайты «через VPN» → приложения → российские сайты → всё остальное.

**Расширение Chrome**
- «Через приложение» — браузер идёт через Tunnelka (любой протокол), из расширения можно подключить и отключить VPN и выбрать сервер;
- «Свой прокси» — работает без приложения с HTTP, HTTPS и SOCKS5-серверами;
- выбор сайтов: все / только из списка / все кроме списка, кнопка «Добавить текущий сайт»;
- защита от утечки IP через WebRTC;
- если VPN в приложении отключился, расширение само снимает прокси, чтобы браузер не остался без интернета.

## Установка

### Готовый установщик через GitHub (проще всего)

Подробная инструкция для браузера — в файле [GITHUB.md](GITHUB.md).

1. Создайте репозиторий на GitHub и загрузите туда эту папку.
2. Откройте вкладку **Actions** → workflow **Build** → дождитесь окончания (≈10 минут).
3. Скачайте артефакт `tunnelka-windows`: в нём установщик `Tunnelka_1.0.0_x64-setup.exe` и `tunnelka-extension.zip`.

Чтобы получить релиз со ссылкой на скачивание, создайте тег: `git tag v1.0.0 && git push --tags`.

### Сборка на своём компьютере с Windows

Нужны [Rust](https://rustup.rs), [Node.js 20+](https://nodejs.org) и Visual Studio Build Tools (рабочая нагрузка «Разработка классических приложений на C++»). WebView2 уже есть в Windows 10/11.

```powershell
npm install
npm run fetch-core      # скачает sing-box.exe, xray.exe и базы geosite/geoip
npm run build           # установщик появится в target\release\bundle\nsis\
```

Для разработки: `npm run dev`. Режим TUN требует прав администратора — запускайте терминал от имени администратора. Установленное приложение запрашивает права само.

### Расширение для Chrome

1. Откройте `chrome://extensions`, включите «Режим разработчика».
2. «Загрузить распакованное расширение» → выберите папку `extension` (или распакуйте `tunnelka-extension.zip`).
3. В приложении: **Настройки → Расширение для Chrome** → «Скопировать токен».
4. В расширении: «Связь с приложением» → вставьте токен → «Сохранить».

Работает также в Edge, Яндекс Браузере, Brave и других браузерах на Chromium.

## Как пользоваться

1. **Серверы и подписки** → вставьте ссылку на подписку → «Добавить».
2. Выберите сервер или «Автовыбор».
3. **Подключение** → нажмите на тоннель.
4. При необходимости настройте **Раздельное туннелирование** → «Сохранить» (подключение перезапустится само).

## Структура проекта

```
core/          Rust-библиотека: разбор ссылок, подписок, генерация конфига sing-box (с тестами)
src-tauri/     приложение: процесс ядра, системный прокси, трей, API для расширения
ui/            интерфейс приложения (HTML/CSS/JS без сборщика)
extension/     расширение Chrome (Manifest V3)
scripts/       загрузка ядра, упаковка расширения
```

Тесты ядра: `cargo test -p tunnelka-core`.

Локальные порты по умолчанию (меняются в настройках):

| Порт | Назначение |
|------|------------|
| 2080 | HTTP/SOCKS5-прокси для системы и других программ |
| 2081 | вход для расширения браузера (всегда через VPN) |
| 2082 | API для расширения (нужен токен) |
| 2083 | Clash API ядра (нужен токен) |
| 10800+ | локальные SOCKS-входы Xray, по одному на сервер (только 127.0.0.1) |

Данные хранятся в `%APPDATA%\app.tunnelka.client\` (`state.json` — подписки и настройки, `config.json` — последний конфиг sing-box).

## Ограничения

- WireGuard пока не поддерживается.
- Подписки в формате Clash YAML не поддерживаются. Если панель отдаёт такой формат, смените User-Agent в настройках (например, на `v2rayN/7.10.0` — тогда панели отдают обычный список ссылок).
- Из JSON-конфигов Xray берётся только основной outbound: цепочки (`dialerProxy`, фрагментация) не переносятся.
- Chrome не умеет авторизацию для SOCKS5-прокси, поэтому в режиме «Свой прокси» логин и пароль работают только для HTTP/HTTPS.
- Установщик не подписан сертификатом, поэтому Windows SmartScreen при первом запуске покажет предупреждение («Подробнее» → «Выполнить в любом случае»).
